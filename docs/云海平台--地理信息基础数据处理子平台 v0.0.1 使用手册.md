# 云海平台--地理信息基础数据处理子平台 v0.0.1 使用手册

## 文档说明

本手册面向部署人员、平台管理员和地理信息数据操作人员，说明 Ocean Admin Service 中地理信息基础数据处理子平台的安装、账号使用、原始数据管理、静态瓦片处理及服务发布方法。本文以仓库当前源码和部署脚本为准；示例服务地址统一使用 `http://127.0.0.1:8090`，实际部署时应替换为可访问地址。

### 角色与职责

| 角色 | 主要职责 | 源码中的权限边界 |
| --- | --- | --- |
| 部署人员 | 准备 Java、PostgreSQL、Redis 或 Docker 环境，配置密码和数据目录，启动及维护服务 | 操作主机、容器、数据库及配置文件 |
| 平台管理员 | 登录管理平台，创建用户、分配角色、重置密码、解锁账号 | `SUPER_ADMIN`、`ADMIN` 可访问成员和日志管理接口 |
| 数据操作员 | 创建数据集、上传数据、提交处理任务、发布和停用服务 | 角色类型 `DATA_OPERATOR` 用于数据管理；但本版本 GIS 接口存在下述鉴权例外 |
| 审查员 | 查看平台数据，不执行平台写操作 | 非 GIS 接口中，`REVIEWER` 仅允许 GET、HEAD、OPTIONS |
| 普通用户 | 登录业务平台，使用面向普通用户的业务能力 | `USER`、`NORMAL_USER` 不允许访问一般的数据管理平台接口 |

> **v0.0.1 安全现状：** `RolePermissionInterceptor` 虽拦截 `/api/**`，但对所有 `/api/gis...` 路径直接放行。因此本手册涉及的数据集、文件、处理任务和发布管理接口目前**没有服务端强制登录或角色校验**。即使客户端携带 Bearer Token，拦截器也会在解析会话前放行。生产部署必须通过反向代理、网关、内网隔离或防火墙限制这些管理接口，并在后续版本补齐服务端鉴权。公开资源接口 `/terrain/**` 和 `/imagery/**` 的设计本身即为免业务鉴权访问。

### 接口约定

- 管理 API 基址：`http://127.0.0.1:8090`。
- 交互式接口文档：服务启动后访问运行期地址 **/doc.html**。
- 除文件下载、公开瓦片资源、矢量 MVT 和矢量 GeoJSON 要素查询外，控制器通常返回统一 JSON：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

- 分页数据位于 `data` 中，结构为 `current`、`size`、`total`、`records`。
- `code=200` 表示业务成功；部分控制器的业务失败仍可能以 HTTP 200 返回、但响应体 `code=500`，调用方应同时判断 HTTP 状态和响应体 `code`。认证拦截器拒绝访问时会返回 HTTP 401 或 403，响应体 `code` 与之相同。
- 对需要认证的非 GIS API，使用请求头 `Authorization: Bearer <登录返回的 token>`。不要把令牌写入日志、脚本仓库或文档。
- 日期时间筛选参数使用 ISO-8601 格式，例如 `2026-10-13T09:30:00`。

# 2 软件使用

典型业务顺序如下：

1. 管理员准备账号；操作人员登录客户端。
2. 创建与数据类型一致的数据集。
3. 通过分片上传把原始文件纳入文件元数据管理。
4. 从已管理文件、直接上传文件或受控工作空间提交处理任务。
5. 查询任务，等待状态变为 `COMPLETED`。
6. 发布任务生成的影像或地形瓦片集，使用返回的资源地址访问服务。

## 2.1 登录、登出

### 认证接口

| 职能 | 方法与路径 | 关键输入 | 结果 |
| --- | --- | --- | --- |
| 登录 | `POST /api/auth/login` | JSON：`username`、`password`；可选 `platformCode`、`deviceId`、`browser`、`os`、`forceLogin`、`currentToken` | `token`、用户和角色、会话 ID、有效期、并发会话信息 |
| 查询本人 | `GET /api/auth/info` | Bearer Token | 当前 `SysUser` 信息 |
| 验证令牌 | `POST /api/auth/validate-token` | `{"token":"<token>"}` | `true` 或 `false` |
| 确认管理员权限 | `POST /api/auth/confirm-admin-access` | Bearer Token | 管理员返回 `true` |
| 登出 | `POST /api/auth/logout` | Bearer Token | 清理当前登录会话 |

登录示例：

```bash
curl -X POST http://127.0.0.1:8090/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "<用户名>",
    "password": "<密码>",
    "platformCode": "OCEAN_CLOUD",
    "deviceId": "operator-workstation"
  }'
```

成功后只在客户端安全存储 `data.token`。一般受保护接口请求头格式如下：

```text
Authorization: Bearer <token>
```

达到账号的最大并发会话数时，登录响应体 `code` 为 `409`，`data.reason` 为 `MAX_CONCURRENT_SESSIONS_REACHED`。客户端可在用户确认后设置 `forceLogin=true`；不要默认强制挤出其他设备。

登出示例：

```bash
curl -X POST http://127.0.0.1:8090/api/auth/logout \
  -H "Authorization: Bearer <token>"
```

### 2.1.1 管理员登录

**前置条件：** 数据库已有启用状态的 `SUPER_ADMIN` 或 `ADMIN` 用户；Redis 可用；账号未锁定且在有效期内。

1. 使用 `POST /api/auth/login` 登录，管理端建议传 `platformCode: "OCEAN_CLOUD"`。
2. 检查响应 `code=200`，并确认 `data.roleType` 为 `ADMIN`。
3. 如需执行敏感配置操作，可调用 `POST /api/auth/confirm-admin-access` 二次确认当前令牌具有管理员权限。
4. 操作结束后调用登出接口，不要仅关闭浏览器。

仓库的 `db/data/default_data.sql` 定义了一个用户名为 `admin` 的超级管理员记录，但不包含明文密码，且该脚本不会随 Flyway 自动执行。严禁根据哈希猜测或在手册中传播密码。

管理员创建用户使用 `POST /api/member/user/create`。该接口受服务端会话和管理员角色校验。创建前必须确认请求中的角色编码已存在于 `ocean_platform.sys_role`，平台编码已存在于 `ocean_platform.sys_platform`；否则整个创建事务会失败。主要请求字段如下：

```json
{
  "username": "user01",
  "password": "<符合密码策略的初始密码>",
  "realName": "普通用户",
  "status": 1,
  "maxConcurrentSessions": 1,
  "isPermanentValid": 1,
  "roleCodes": ["USER"],
  "platformCodes": ["OCEAN_VISION"]
}
```

`db/data/default_data.sql` 只预置 `SUPER_ADMIN`、`ADMIN`、`USER` 三种角色，没有预置平台记录，也没有预置 `DATA_OPERATOR` 或 `REVIEWER`。用户创建服务在省略授权字段时会默认使用 `NORMAL_USER` 和 `OCEAN_VISION`，这些记录同样不在该脚本中。因此首次创建用户前，部署负责人必须先完成角色和平台基础数据初始化。<!-- VERIFY: 项目实际启用的平台编码、角色清单及初始化方式由部署负责人确认 -->

初始安全策略要求密码至少 8 位，并包含大写字母、小写字母和数字；特殊字符默认不强制。管理员还可通过以下接口维护账号：

- `GET /api/member/user/query`：分页查询用户，参数 `username`、`status`、`current`、`size`。
- `PUT /api/member/user/update`：更新用户资料和授权。
- `PUT /api/member/user/reset-password/{id}`：请求体 `{"newPassword":"<新密码>"}`。
- `PUT /api/member/user/unlock/{id}`：手动解锁，可选请求体 `{"operatorName":"<操作人>"}`。
- `DELETE /api/member/user/{id}`：删除用户。

### 2.1.2 普通用户注册与登录

**普通用户不支持自助注册。** 当前仓库没有 `/register`、`/signup` 或等价 Controller。用户必须由管理员通过 `POST /api/member/user/create` 创建后才能登录。

普通用户登录步骤：

1. 向管理员申请账号，由管理员设置 `USER` 或 `NORMAL_USER` 角色，并安全交付初始密码。
2. 调用 `POST /api/auth/login`，普通用户应传业务平台标识，例如 `platformCode: "OCEAN_VISION"`；普通用户尝试登录数据管理平台会收到“普通用户不可登录数据管理平台”的错误。
3. 检查 `data.roleType` 为 `NORMAL_USER`，并按返回的 `platformCodes` 使用已授权平台。
4. 使用完毕后调用 `POST /api/auth/logout`。

注意：普通用户经过认证后不能访问一般的数据管理接口；但 v0.0.1 的 `/api/gis/**` 因鉴权放行而成为例外。这是服务端安全缺口，不代表普通用户被正式授予 GIS 管理权限，部署侧仍应限制访问。

## 2.2 原始数据管理

原始数据管理负责建立数据集、接收大文件分片、维护文件元数据、下载原始文件、查看上传操作记录和执行受保护的永久删除。

**权限：** 按产品职责应由管理员或数据操作员执行；但 v0.0.1 源码没有对 `/api/gis/**` 强制认证，必须依靠部署侧访问控制。

### 第一步：创建数据集

数据类别必须与后续文件类型和处理类型一致：`0` 影像、`1` 地形、`2` 矢量。

```bash
curl -X POST http://127.0.0.1:8090/api/gis/dataSet/create \
  -H "Content-Type: application/json" \
  -d '{
    "dataSetName": "示例影像数据集",
    "categoryId": 0,
    "description": "用于影像切片演示"
  }'
```

结果 `data` 返回数据集 `id`，后续上传时用作 `Upload-Data-Set-Id`。

| 职能 | 方法与路径 | 关键参数 |
| --- | --- | --- |
| 分页查询 | `GET /api/gis/dataSet/page` | `current`、`size`、可选 `categoryId`、`dataSetName`；自动返回文件代表点 |
| 查询全部 | `GET /api/gis/dataSet/query` | 可选 `categoryId`、`dataSetName` |
| 详情 | `GET /api/gis/dataSet/{id}` | 数据集 ID |
| 数据集地图轮廓 | `GET /api/gis/dataSet/{id}/footprints` | 数据集 ID、可选 `simplifyTolerance`（默认0.001度，0为完整几何） |
| 更新 | `PUT /api/gis/dataSet/update` | `id`、`dataSetName`、`categoryId`、`description` |
| 永久删除 | `DELETE /api/gis/dataSet/{id}` | 级联删除数据集文件和自有矢量数据；活动任务、活动传输或元数据提取存在时拒绝。已发布影像/地形服务基于独立瓦片集继续运行 |

数据集响应的 `fileCount` 和 `totalSizeBytes` 分别为服务端维护的文件数量及总字节数，均只统计未删除且上传完整的管理文件，包括配套文件和空间解析失败文件；客户端不能通过创建或更新数据集设置这两个值。可用空间文件数量请查看 `fileSummary.footprintFileCount`。

卡片地图示例：`GET /api/gis/dataSet/page?current=1&size=10`。每个数据集的 `filePoints` 为已保存的文件代表点列表，无可定位文件时为空数组；`footprints` 为 null。每个点包含 `dataSetId`、`fileId`、`fileName`、`longitude`、`latitude`、`layerKey`、`extentKind`，坐标为 EPSG:4326（经度、纬度）。分页接口不再提供 `includeFootprints` 或 `simplifyTolerance` 参数。

代表点在空间元数据提取完成的同一事务中计算并保存，分页直接读取，不扫描或简化覆盖几何。每个文件只返回一个点：优先选面积最大的面分块并取其内部点；没有面时选最长线分块的中点；只有点时使用点本身。面积、长度按地理平方米、米比较，大小相同按图层键（C排序）与分块序号固定选择。文件来源变更、人工重试、分类变化导致元数据失效时清空点位，重新提取后生成。文件永久删除后点位一并删除。GeoTIFF 点位于有效像元覆盖区内；GeoJSON 当前来源为包围范围，`VECTOR_ENVELOPE` 不保证点位于真实要素内。

列表和详情的 `fileSummary` 包含 `managedFileCount`（上传完整的未删除文件数）、`footprintFileCount`（空间元数据完成且具有已存代表点的文件数）、`pendingMetadataFileCount`、`failedMetadataFileCount`、`notApplicableFileCount`。只有未删除、READY、元数据 COMPLETED 的文件返回代表点；未完成解析的文件不伪造点位。文件数量较大时前端可聚合展示重叠点位。

点击单个数据集查看地图时，调用 `GET /api/gis/dataSet/{id}/footprints?simplifyTolerance=0.001`。响应 `data` 为单个数据集对象，包含名称、`totalSizeBytes`、`fileSummary` 和 `footprints`，`filePoints` 为 null。一次返回该数据集所有已有可用文件/图层的轮廓，不分页、不截断，文件筛选口径与分页一致。`footprints` 为 EPSG:4326 GeoJSON FeatureCollection；无可用轮廓时 `features` 为空数组，数据集不存在或已删除时返回错误。`simplifyTolerance` 默认0.001，范围0至1的有限数值，单位为度，0返回完整几何。每个 Feature 的 `properties` 包含 `fileId`、`fileName`、`layerKey`、`extentKind`、`simplified` 和 `simplifyTolerance`。GeoTIFF 为有效像元轮廓，GeoJSON 当前为包围范围，其他格式尚未扩展解析。完整几何或大量碎片可能产生较大响应。

### 第二步：分片上传原始文件

接口为 `POST /api/gis/uploads/chunks`，请求体是当前分片的原始二进制，`Content-Type` 必须为 `application/octet-stream`。

| 请求头 | 含义 |
| --- | --- |
| `Upload-Request-Id` | 客户端生成的批次幂等 ID，只能含字母、数字、下划线或连字符，长度 8～64 |
| `Upload-Data-Set-Id` | 目标数据集 ID |
| `Upload-File-Index` | 文件序号，从 `0` 开始，按顺序上传 |
| `Upload-File-Count` | 本批次文件总数，最多 100 |
| `Upload-File-Name` | URL 编码后的原始文件名 |
| `Upload-File-Size` | 当前文件总字节数 |
| `Upload-Total-Size` | 整个批次所有文件总字节数 |
| `Upload-Offset` | 当前分片在文件中的起始字节，首块为 `0`，后续使用响应的 `nextOffset` |
| `Upload-Chunk-Size` | 当前请求体字节数，必须和 `Content-Length` 一致 |

默认限制为单文件 25GB、单批次 100GB、单分片 128MB；服务还要求保留至少 20GB 可用空间。上传超时未活动 6 小时后会进入清理流程。

每个响应的 `data` 包括 `requestId`、`taskId`、`dataSetId`、`fileIndex`、`nextOffset`、`duplicate`、`fileCompleted`、`fileFailed`、`taskCompleted`、`completedCount`、`failedCount`、`status`。客户端必须保存 `requestId`，并严格使用 `nextOffset` 续传；重复分片可幂等返回。

文件扩展名会按数据集类别检查：

- 影像：`tif`、`tiff`、`img`、`jp2`、`png`、`jpg`、`jpeg`、`tfw`、`prj`、`aux`、`xml`。
- 地形：`tif`、`tiff`、`dem`、`hgt`、`terrain`、`asc`、`prj`、`xml`。
- 矢量：`shp`、`shx`、`dbf`、`prj`、`cpg`、`sbn`、`sbx`、`geojson`、`json`、`kml`、`kmz`、`gpkg`。

“允许上传”不等于“当前可切片”。当前实际接入的影像与地形处理引擎只接受 `tif/tiff`；矢量处理引擎尚未接入。

### 第三步：查询、下载和永久删除文件

| 职能 | 方法与路径 | 关键参数或结果 |
| --- | --- | --- |
| 文件分页 | `GET /api/gis/filemeta/page` | `current`、`size`；可选 `dataSetId`、`categoryId`、`originalName`、`extension`、`uploadStatus` |
| 文件详情 | `GET /api/gis/filemeta/{id}` | 返回存储信息、大小、SHA-256、状态和错误信息 |
| 文件下载 | `GET /api/gis/filemeta/{id}/download` | 返回原始二进制；支持单区间 Range 断点续传和 HEAD 探测 |
| 更新元数据 | `PUT /api/gis/filemeta/update` | 使用文件元数据对象；不要随意修改存储路径字段 |
| 永久删除 | `DELETE /api/gis/filemeta/{id}` | 永久删除元数据及对应物理文件，不可恢复；客户端须二次确认，活动任务引用时返回409 |

文件状态含 `PENDING`、`READY`、`FAILED`。只有 `READY` 文件能用于“已管理文件”处理任务。通过分片上传时元数据由系统自动形成，日常操作不应再手工调用 `POST /api/gis/filemeta/create` 伪造已上传文件。

### 第四步：查看文件传输记录

- `GET /api/gis/file-transfer-records`：分页查询上传、下载传输批次记录，可通过 `operationType=IMPORT|EXPORT` 筛选。
- 可选筛选：`dataSetId`、`categoryId`、`recordNo`、`recordStatus`、`originalName`、`extension`、`uploadStatus`、`createTimeStart`、`createTimeEnd`。
- `GET /api/gis/file-transfer-records/{recordNo}`：查看传输批次及各文件明细。

记录用于定位传输批次成功、部分失败或失败原因。若客户端丢失上传响应，可通过 `requestId` 对应的任务号和文件传输记录核对，而不要新建不同批次重复上传。

## 2.3 数据处理

数据处理把 GeoTIFF 或受控目录转换为静态影像瓦片或 Cesium Quantized Mesh 地形瓦片。提交接口异步返回任务信息，处理完成前应通过任务查询观察状态。

**实际支持范围：** `IMAGERY` 和 `TERRAIN` 已接入引擎；`VECTOR` 虽存在枚举和请求参数模型，但没有处理引擎，提交会失败，不应作为 v0.0.1 可用功能宣传。

### 三种提交方式

| 来源 | 方法与路径 | 适用情形 | 核心约束 |
| --- | --- | --- | --- |
| 直接上传并处理 | `POST /api/gis/task/process` | 文件尚未纳入元数据管理 | `multipart/form-data`，`request` 为 JSON、`files` 为文件；最多 100 个、总计 5GB |
| 已管理文件 | `POST /api/gis/task/process-managed` | 推荐流程；文件已经分片上传并为 `READY` | JSON 中传 `fileMetaIds` |
| 受控工作空间 | `POST /api/gis/task/process-workspace` | 处理服务器已配置目录中的文件或目录 | 只接受工作空间编码和根目录内相对路径；默认 `default`、`.` |

影像和地形任务均支持多个 `tif/tiff` 统一生成一个静态瓦片集。已管理文件通过同一次请求的 `fileMetaIds` 提交，最多 100 个；工作空间目录输入仅支持单个地形目录。

影像逐源进行窗口预处理和概览构建，按分块空间索引在目标瓦片阶段合成。重叠区域优先使用分辨率较高的源，同分辨率时输入列表中靠后的源优先；NoData、独立 mask 和 alpha 无效像素保留下层数据，合法黑色不作为空洞。未指定 `maxZoom` 时逐源计算可用层级，每层合并覆盖范围；显式指定时允许上采样。预计瓦片按覆盖区去重，在预处理前检查 `GIS_IMAGERY_MAX_TILE_COUNT` 上限。

例如“全球500米-影像”可在同一次请求中提交全部 8 个文件，选择 `EPSG:4326`、`XYZ`、`minZoom=0`、`maxZoom=7`，完整全球覆盖生成 43,690 张瓦片。`EPSG:3857` 会裁去约 ±85.0511° 以外的极区。单个源仍须位于现有支持的坐标范围内，不支持跨日期变更线或 0～360° 经度布局。

已管理影像文件示例：

```bash
curl -X POST http://127.0.0.1:8090/api/gis/task/process-managed \
  -H "Content-Type: application/json" \
  -d '{
    "processingType": "IMAGERY",
    "taskName": "多源影像统一切片",
    "fileMetaIds": [101, 102],
    "parameters": {
      "targetCrs": "EPSG:3857",
      "tileProfile": "XYZ",
      "outputFormat": "PNG",
      "minZoom": 0,
      "maxZoom": 12,
      "resampling": "BILINEAR",
      "transparent": true
    }
  }'
```

地形 `parameters` 的主要字段：

| 字段 | 规则或默认值 |
| --- | --- |
| `targetCrs` | 固定 `EPSG:4326` |
| `tileProfile` | 固定 `TMS` |
| `outputFormat` | 固定 `QUANTIZED_MESH` |
| `minZoom`、`maxZoom` | 0～22；`minZoom` 默认 0 |
| `geoid` | 默认 `Ellipsoid` |
| `interpolationType` | `NEAREST` 或 `BILINEAR`，默认 `BILINEAR` |
| `rasterMaxSize`、`mosaicSize` | 可选正整数 |
| `calculateNormals` | 默认 `true` |
| `continuePrevious`、`leaveTemp` | 默认 `false` |
| `generateLayerJson` | 默认 `true`；发布地形要求输出存在运行期产物 **layer.json** |

影像 `parameters` 的主要字段：

| 字段 | 规则或默认值 |
| --- | --- |
| `targetCrs` | `EPSG:3857` 或 `EPSG:4326`，默认 `EPSG:3857` |
| `tileProfile` | `XYZ` 或 `TMS`，默认 `XYZ` |
| `outputFormat` | `PNG`、`JPEG` 或 `JPG`，默认 `PNG` |
| `minZoom`、`maxZoom` | 0～22；为空时自动计算 |
| `resampling` | `NEAREST` 或 `BILINEAR`，默认 `BILINEAR` |
| `transparent` | PNG 默认 `true`；JPEG/JPG 固定为 `false` |

### 查询任务与判断结果

- `GET /api/gis/task/page`：分页查询任务。可选 `taskNo`、`taskName`、`processingType`、`sourceType`、`taskStatus`、`dataSetId`、`createTimeStart`、`createTimeEnd`。
- `GET /api/gis/task/{taskId}`：查看参数快照、输入列表和生成的唯一瓦片集。

任务状态：`QUEUED`、`RUNNING`、`COMPLETED`、`PARTIAL_FAILED`、`FAILED`。只有 `COMPLETED` 且瓦片集完整的任务可进入发布流程。详情中的 `tileSet.id`、`tileSet.outputKey`、层级、坐标系和格式用于核对产物；失败时先查看 `task.errorMessage` 及各 `inputs[].errorMessage`。

提交成功返回 `taskId`、`tileSetId`、`taskNo`、`sourceType`、`processingType`、`outputKey`、`totalCount`、`status`。建议保存 `taskId`，以它作为发布前查询依据。

运行期进度通过 `/ws/task` 实时推送。超过 6 小时未更新的运行态任务快照由服务端定期自动清理；持久化任务仍通过 `/api/gis/task/page` 查询。

## 2.4 服务发布

服务发布把已完成任务的静态瓦片目录登记为可访问服务。地形和影像分别有发布接口；矢量发布接口在 v0.0.1 中不存在。

**前置条件：** 源任务已 `COMPLETED`；地形输出包含运行期产物 **layer.json**；影像输出包含运行期产物 **tilejson.json** 和 **manifest.json**；`GIS_PUBLIC_BASE_URL` 已配置为客户端可访问地址。

### 发布影像服务

1. 调用 `POST /api/gis/imagery-publications/{sourceTaskId}/publish`。
2. 保存返回的 `serviceCode`、`serviceUrl`、`tileJsonUrl` 和 `tileUrlTemplate`。
3. 用 `GET /imagery/{serviceCode}/tilejson.json` 验证 TileJSON；空路径 `/imagery/{serviceCode}/` 也映射到 TileJSON。
4. 客户端按 `tileUrlTemplate` 请求 `{z}/{x}/{y}.png` 或 JPEG/JPG 瓦片，Y 轴含义以返回的 `tileProfile` 和 TileJSON `scheme` 为准。

管理接口：

- `GET /api/gis/imagery-publications/page`：按 `serviceCode`、`status`、`dataSetId`、发布时间范围分页查询。
- `GET /api/gis/imagery-publications/{serviceCode}`：查询单个发布信息。
- `PUT /api/gis/imagery-publications/{serviceCode}/disable`：停用服务。

### 发布地形服务

1. 调用 `POST /api/gis/terrain-publications/{sourceTaskId}/publish`。
2. 保存返回的 `serviceCode` 和 `serviceUrl`。
3. 请求 `GET /terrain/{serviceCode}/layer.json` 验证服务；空路径 `/terrain/{serviceCode}/` 也映射到运行期产物 **layer.json**。
4. Cesium 客户端使用响应中的 `serviceUrl` 创建地形提供者。

管理接口：

- `GET /api/gis/terrain-publications/page`：按 `serviceCode`、`status`、`dataSetId`、发布时间范围分页查询。
- `GET /api/gis/terrain-publications/{serviceCode}`：查询单个发布信息。
- `PUT /api/gis/terrain-publications/{serviceCode}/disable`：停用服务。

### 统一查询和停用说明

`GET /api/gis/publications/page` 可统一查看地形、影像和矢量类型记录，筛选参数包括 `processingType`、`serviceCode`、`status`、`dataSetId`、`publishTimeStart`、`publishTimeEnd`。当前可实际创建的发布类型只有 `TERRAIN` 和 `IMAGERY`。

发布状态为 `PUBLISHED` 或 `DISABLED`。停用后资源解析服务会拒绝继续提供该发布目录；停用不是删除处理任务或原始数据。公开资源响应包含 ETag、Last-Modified 和 24 小时公共缓存策略，更新或停用时需考虑客户端及中间缓存。

# 5 矢量数据集：前端重新接入说明

本节对应2026-10-23保形渲染修复后的默认样式版后台，不是静态矢量切片或对外发布服务。2026-10-22的结构升级已清理升级前的历史矢量记录；那些ID不可再用。本轮仅修复渲染，不清理升级后已导入的数据，不要求再次创建数据集或导入；更新前后端后刷新工作区并重建上下文即可。影像和地形接口不受此项调整影响。

## 5.1 必须替换的接入方式

- 地图主流程由“逐图层拉 GeoJSON 后本地套样式”改为“一个数据集、一个当前视窗上下文、按上下文取 MVT”。不能为每个图层分别创建上下文，否则无法落实全视窗统一密度预算。
- 停用旧路径 `POST /api/gis/vector/layers/{layerId}/render-contexts`、`GET /api/gis/vector/layers/{layerId}/tiles/{z}/{x}/{y}.mvt`、`GET /api/gis/vector/layers/{layerId}/clusters/{clusterId}/features`。这些路径已移除，无兼容别名；改用下文 datasets 路径。
- `GET /api/gis/vector/layers/{layerId}/features` 不再用于地图显示：bbox 必填，返回要素属性及来源引用，geometry 为 null。不得通过翻页拼接全量图形、下载原始文件或读取全量样本绕过预算。
- `GET /api/gis/vector/layers/{layerId}/default-style` 返回结构已变为有效样式信息，不能再按“必有一份 schemaVersion=1 默认方案”处理。它用于配置面板，不用于驱动全量 GeoJSON 渲染。
- 分类 ID、数据集 ID、图层 ID、要素 ID、样式 ID 均按字符串保存和传递，禁止转为 JavaScript Number。版本及部分 Long 计数也可能返回字符串；ID 和版本不做浮点运算。

## 5.2 创建数据集与加载分类树

1. 保留 `POST /api/gis/dataSet/create`，请求至少包含 `{"dataSetName":"浙江矢量数据","categoryId":2}`。服务端在同一事务复制默认模板并创建分类树，前端不提交模板 JSON，也不逐项创建分类。
2. `GET /api/gis/dataSet/{dataSetId}`：详情新增只读 `vectorStyle` 摘要，含 snapshotId、templateId、templateVersion、styleVersion、dataRevision、displayRevision。创建响应和列表不保证包含该摘要，进入详情后再读取。
3. `GET /api/gis/vector/datasets/{dataSetId}/style`：读取该数据集不可变的完整默认规则，响应为统一包装的 `DataSetStyle`，含 definition（schemaVersion=2）。仅作规则展示和配置参考，后端文件变化不会追改已有数据集。
4. `GET /api/gis/vector/datasets/{dataSetId}/groups`：读取分类树，保存响应头 ETag。每个节点含 id、parentId、groupKey、name、nodeType、geometryType、assignable、defaultStyleKey、enabled、version、layerCount、featureCount、children；统计包含后代，不内嵌要素几何或所有图层。
5. `GET /api/gis/vector/layers?dataSetId={id}&groupId={id}&sourceFileId={id}&current=1&size=50`：按分类或来源懒加载图层。groupId、sourceFileId 可省略；传 groupId 时必须同时传所属 dataSetId。size 为1至100，分类筛选匹配该节点自身，目录节点应展开至可挂载叶节点后查询。

`groups` 接口的 id 是数据集私有数据库 ID，groupKey 才对应模板 `definition.groups[].id`；defaultStyleKey 对应 `definition.styles[].id`。例如模板键 `hydro-river` 不能直接作为 presentation.groupId 提交。图层的 groupId 指向运行时分类，originalGroupId 保存首次入库分类。文件名、图层名不是分类绑定依据。

矢量图层摘要新增 groupId、originalGroupId、geometryType（POINT/LINE/POLYGON）、assignmentMode（AUTO/MANUAL）、enabled、styleMode、presentationVersion。图层树应按 groupId 挂载，而非假定一个文件只对应一个图层。数据集禁止直接与其他类别相互切换。

## 5.3 批量导入：自动归组与强制未知

继续使用 `POST /api/gis/uploads/chunks`，请求体仍是单块二进制流，原有 Upload-* 头不变。新增头：

```http
Upload-Vector-Placement: AUTO
```

- AUTO（省略时默认）：按数据集快照逐要素匹配几何与属性；未识别的点、线、面分别进入未知分类。
- UNKNOWN：整批绕过自动识别，按几何类型进入未知分类，适合明确不希望套用既有属性规则的其他来源数据。
- 同一 Upload-Request-Id 的整个批次必须保持归组方式不变；快照 ID 由后端固定，不由前端指定。
- 不新增来源适配器。字段规范满足当前规则的数据可自动识别；不能仅凭来源名称、文件名或 features[0] 推断整个文件。
- 一个文件包含多个业务类型或几何类别时会拆成多层。GeometryCollection 递归拆分；MultiPoint/MultiLineString/MultiPolygon 保持多部件整体。源 properties、Feature.id、源序号和分量路径保留。
- 未知层默认 `enabled=false, styleMode=UNCONFIGURED`，即使勾选瞬时显示列表，也不能绕过显式配置。

`fileCompleted=true` 仅表示文件上传完成，`importCompleted=false`、EXTRACTING_METADATA 表示仍在提取与拆层；此时 vectorLayerIds 可以为空。继续沿用传输记录/进度通知，确认文件 metadataStatus=COMPLETED 后再刷新分类树、图层列表并创建渲染上下文，不能仅因上传进度100%就读取地图数据。

文件/传输摘要新增 vectorPlacement、vectorDatasetStyleId；文件详情的 `spatialReferences[].extraMetadata.vectorImport` 提供 layerIds、sourceFeatures、parts、unknownParts、warnings、groupCounts。sourceFeatures 是源要素数量，parts 是分量数量，二者可能不相等；groupCounts 使用模板业务键。直接创建文件元数据的 `/api/gis/filemeta/create` 也可提交 vectorPlacement，但快照仍由后端绑定；建立后的归组方式不可变更。

## 5.4 新渲染协议：上下文与瓦片

### 创建当前视窗上下文

`POST /api/gis/vector/datasets/{dataSetId}/render-contexts`

```json
{
  "bbox": [119.9, 29.9, 120.2, 30.2],
  "displayZoom": 12.5,
  "widthPixels": 800,
  "heightPixels": 600
}
```

bbox 为 WGS84 的 west,south,east,north 数组，纬度严格限制为±85.0511287798066°，经度为±180°。前端 wrapX=false，先将投影视窗与 EPSG:3857 世界范围求交，再转为经纬度；不可发送超出世界范围的经度，也不可使用舍入后的纬度极限。west>east 表示跨日期变更线。displayZoom 是当前相机连续层级，不得提前取整；本模板允许0至18。宽高是地图容器 CSS 像素，各为1至8192，不乘 devicePixelRatio。

可选 enabledGroupIds、enabledLayerIds 为运行时 ID 数组，分别最多1024项。省略/null 表示不额外限制，空数组表示本次不选择任何对象；两者同时提交时取交集。选中目录可涵盖后代，但不能越过服务器保存的父级开关、图层开关或未配置状态。瞬时筛选不保存配置；持久显隐使用5.5节接口。

统一包装响应的 data 含 contextId、dataSetId、styleVersion、dataRevision、displayRevision、bbox、displayZoom、widthPixels、heightPixels、budget、objectCount、candidateCount、detailReduced、cutoffMinZoom、cutoffPixelSize、maxZoom、expiresAt，以及诊断用 plans/policy。contextId 是不透明引用，只提交它读取瓦片；不要将计划回传、自行改写规则或假定每次请求都返回不同 ID。

800×600 CSS 像素的当前模板预算为600个逻辑显示对象。candidateCount 是级别、属性和基础像素过滤后的候选数，objectCount 是保形细节筛选后保留的源分量数；一个对象的填充、边界及标注仅计一次，不按每瓦片数量或 GPU 绘制调用数重复计数。detailReduced 表示已筛除较次要细节；cutoffMinZoom/cutoffPixelSize 是冻结的筛选阈值，仅用于诊断。点、线、面均不做网格聚合；点和行政边界受保护，其他线面按命中规则开始级别升序、视窗内屏幕尺寸降序选择，等值桶整体保留或排除，不按任意ID取前N条。保护对象本身超预算或筛选后无对象可显示时返回422，不伪装成空数据。所有启用层共用该预算，不逐层累加预算。手动配色和级别不能关闭全局密度与像素约束。

### 读取显示瓦片

`GET /api/gis/vector/datasets/{dataSetId}/tiles/{z}/{x}/{y}.mvt?contextId={contextId}`

成功返回 `application/vnd.mapbox-vector-tile` 二进制，不是统一 JSON。z/x/y 是地图实际请求的有效 XYZ 整数坐标，z 不超过上下文 maxZoom；不要把连续 displayZoom 直接写入 z，也不要固定请求 z=0 验证高层级细小要素。显示规则仍使用上下文的连续 displayZoom。上下文与瓦片 URL 必须一起更新，不能把上一个 bbox 的瓦片复用到新视窗。

MVT 内的 source-layer 固定为 `features`，业务图层、分类和符号通过以下属性区分：

- `_vector_representation_id`：显示对象稳定键，可用于前端去重；不要将其当作源要素 ID。
- `_vector_render_role`：FILL（面填充，禁止描边）、OUTLINE（源真实边界线，正常描线）、GEOMETRY（点/线符号）、LABEL（独立点锚，只绘文字，不绘圆点）。客户端必须按角色消费，不再对裁剪面自动描边或自动生成标注。
- `_vector_feature_id`、`_vector_layer_id`：对应的入库要素 ID、图层 ID，使用单要素详情接口进入编辑。
- `_vector_group_id`、`_vector_rule_id`：运行时分类和命中的规则键。
- `_vector_symbol`：JSON字符串，客户端解码为点/线/面配色、宽度、半径、透明度、虚线等符号。按现有地图引擎的样式回调或样式分桶消费，不直接套用某个引擎的专用样式协议。
- `_vector_category`、`_vector_feature_count`：当前渲染部件的几何类别与分量数（固定1）；面拆出 OUTLINE 线和 LABEL 点是显示部件，不是聚合。
- `_vector_label`、`_vector_render_order`：可选标注与绘制顺序。客户端仍应做标注避让，本模板字体大小为11 CSS像素；服务端的标注数量上限不等于客户端文字碰撞检测。

MVT 不包含全量源属性；空值属性可能被编码器省略。显示部件不能回写为真实几何。简化先于瓦片裁剪，面真实边界在裁剪前提取；MVT extent=4096、buffer=1024，前端 renderBuffer=64 CSS像素。一个源对象的标注锚点固定，仅输出到唯一XYZ归属瓦片；客户端不对其他部件补标注。成功的空字节瓦片是合法空结果，不得改调 GeoJSON 或原始文件补齐。

### 前端请求生命周期

进入工作区先取分类和图层摘要，再创建一个数据集上下文并设置该上下文的瓦片 URL。平移、缩放、容器尺寸变化或瞬时筛选变化后，合并高频事件、取消过时请求并创建新上下文；只接纳最后一次视窗请求的响应。导入完成、要素编辑/删除、图层移组/样式/显隐变更、分类开关变更后，也应刷新摘要并重建上下文。不要依赖旧 URL 的客户端瓦片缓存继续显示。

## 5.5 分类开关与图层挂载/样式

分类持久开关使用 `PATCH /api/gis/vector/datasets/{dataSetId}/groups/{groupId}/visibility`，请求体 `{"enabled":false}`，If-Match 原样取自最新 `GET .../groups` 响应头 ETag。关闭任意父节点会使所有后代隐藏，子层不能单独绕过父开关。成功后重读分类树获取新 ETag，再重建上下文；不要自行拼接 ETag。

图层挂载、样式和开关统一使用 `PUT /api/gis/vector/layers/{layerId}/presentation`。提交前通过 `GET /api/gis/vector/layers/{layerId}` 获取该层最新 ETag，If-Match 必须使用图层 ETag，不能用分类树 ETag、有效样式 ETag 或某份样式方案的 ETag。

移入同数据集、同几何类型的可挂载分类并继承其默认基础样式：

```json
{
  "groupId": "目标分类数据库ID",
  "styleMode": "INHERIT_TARGET_GROUP",
  "enabled": true
}
```

保留未知分类或在业务分类内使用自定义样式：

```json
{
  "groupId": "同几何类型分类数据库ID",
  "styleMode": "CUSTOM",
  "enabled": true,
  "customStyle": {
    "minZoom": 11,
    "maxZoom": 22,
    "symbol": {"color": "#247BC0", "width": 2}
  }
}
```

上述示例 symbol 为线符号；点使用 color/radius/opacity/strokeColor/strokeWidth，面使用 fillColor/fillOpacity/strokeColor/strokeWidth/strokeOpacity，线还支持 dashArray。颜色为 #RRGGBB，透明度0至1，半径/线宽0.5至12 CSS像素，描边宽度0至12。开始级别0至18、结束级别不大于22且大于开始级别，显示区间为左闭右开。结束级别22不表示地图允许显示到22，地图仍受上下文 maxZoom 限制。

- 继承模式不能同时提交 customStyle；未知分类不允许继承其占位样式，必须显式 CUSTOM 配置后才能启用。
- 目标必须 assignable=true，目录节点不是挂载目标；不得跨数据集或跨几何类别。
- 一次 PUT 原子保存三项配置，成功返回新图层及新图层 ETag。即使只切换图层开关，也须带上完整 groupId/styleMode；CUSTOM 模式须带完整 customStyle 级别和符号草稿，不要以多个独立请求拼成非原子操作。
- 手动保存后 assignmentMode=MANUAL，originalGroupId、layerKey、数据版本和来源引用保留。继承目标只应用其基础样式，不再因源 fclass 命中自动分类专用覆盖规则；不会重读文件、重新识别或合并其他图层。
- `GET .../layers/{layerId}/default-style` 返回 layerId、source（GROUP/CUSTOM/UNCONFIGURED）、groupId、styleId、version、presentationVersion、configured、definition。styleId 在 GROUP 模式下是模板样式业务键，在 CUSTOM 模式下是方案数据库ID，不能混用。

已有 `/layers/{layerId}/styles` 列表/创建、`/styles/{styleId}` 详情/更新/删除、`/styles/{styleId}/default` 切换、`/styles/{styleId}/match` 单要素匹配接口保留。它们管理 schemaVersion=1 图层自定义方案，不是数据集默认模板编辑接口；若面板继续使用，保存有效 CUSTOM 方案后同样重建上下文。默认样式不再保证是方案表中的一行；不要仅靠 styles 列表判断一个继承层是否已配置。

## 5.6 要素点击、属性列表及编辑

- 点击任意显示部件，通过 _vector_layer_id 和 _vector_feature_id 查询单要素详情；已移除聚合成员接口及成员面板，不再调用 `/datasets/{id}/clusters/{clusterId}/features`。
- 普通属性列表：`GET /api/gis/vector/layers/{layerId}/features?bbox=west,south,east,north&limit=200&cursor={cursor}`。bbox 是逗号分隔字符串，limit 为1至1000，每页还有字节预算约束。返回未包装的 GeoJSON FeatureCollection，但 geometry=null；按 hasMore/nextCursor 继续，不把它作为地图数据源。
- 编辑详情：`GET /api/gis/vector/layers/{layerId}/features/{featureId}` 返回未包装的完整 GeoJSON Feature 和要素 ETag。source 含 featureIndex、featureId（原始 Feature.id）、geometryPath、classificationRuleKey；不要把 source.featureId 与顶层入库 id 混淆。
- 新增/替换/删除仍使用 `POST .../features`、`PUT .../features/{featureId}`、`DELETE .../features/{featureId}`。替换和删除携带单要素 ETag，保留原 XY/XYZ 维度，几何类别须与图层一致；不能用 MVT 裁剪/简化几何作为编辑原稿。
- `DELETE /api/gis/vector/layers/{layerId}` 路径不变，但 If-Match 应来自最新图层详情（现在同时包含数据与显示版本）。删除成功后刷新分类统计、图层列表及上下文。

## 5.7 错误与联调验收

- 400：参数无效、bbox缺失、目标几何不一致等，修正请求；不要重试全量预览。
- 404：对象不属于当前资源或不存在，刷新对应摘要。
- 409：数据、显示或样式变化导致上下文失效，重新创建上下文并替换瓦片URL；对象不存在样式快照时也会409，不能无限重试。
- 410：上下文过期，重建后重试当前视窗。
- 412/428：ETag过期/缺少If-Match，重新读取相应分类树、图层、要素或样式详情后由用户确认保存，不能盲目覆盖。
- 422：保护对象、等值桶无法安全筛选、规则、启用层（最多1024个）或安全显示字节预算超限，缩小视窗或减少启用对象；不请求原始几何兜底。
- 503：空间查询排队、超时、Redis或数据库暂不可用，有限退避重试；同样禁止原始数据回退。

MVT 请求失败时响应体可能为 JSON 错误，不可把错误 JSON 交给 PBF 解码器；统一先检查 HTTP 状态，再按 Content-Type 解析。普通管理接口还应检查统一响应 code。

已用升级后的实际服务完成以下回归：创建40节点分类树；4个源要素拆成5层、2个未知层默认隐藏；连续12.5级生成有效MVT；未知层配置后可见并可手动移入河流组；原属性和来源ID保留；显示变更后旧上下文409、过期分类ETag412；全部分类关闭后返回空瓦片；无bbox属性查询400。临时数据与测试上传副本已清理。前端还应验收快速拖动/缩放时旧响应不覆盖新视窗，以及高DPI屏使用CSS尺寸计算预算。

本轮渲染修复无需更改数据库表或重新导入数据。新建数据集使用模板v2，已有数据集保持不可变快照及分类配色；渲染服务统一不执行网格聚合。新上下文使用独立缓存命名空间，发布后前端须刷新并重建上下文，旧上下文按410处理。

## 常见问题

### 登录成功但管理接口返回 401

确认请求头严格为 `Authorization: Bearer <token>`，Redis 正常，令牌未过期且会话未被管理员撤销。不要把整个登录响应对象当作令牌。

### 普通用户为什么不能注册

当前版本没有自助注册接口。这是明确的账号治理边界，应由管理员创建账号并分配角色和平台权限。

### 上传第一块就失败

检查 `Upload-Request-Id` 格式、数据集 ID、文件扩展名与数据集类别、`Content-Length` 与 `Upload-Chunk-Size`、单块大小和磁盘剩余空间。新批次必须从 `fileIndex=0` 且 `offset=0` 开始。

### 已上传文件不能提交任务

确认文件元数据状态为 `READY`；影像与地形处理只接受 `tif/tiff`。允许上传的其他旁车文件或数据格式不代表切片引擎已经支持。

### 任务提交后不能发布

先查询 `GET /api/gis/task/{taskId}`，任务必须为 `COMPLETED`。影像必须生成运行期产物 **tilejson.json** 和 **manifest.json**，地形必须生成运行期产物 **layer.json**。

### 返回的服务地址无法从浏览器访问

检查 `GIS_PUBLIC_BASE_URL` 是否配置为浏览器可达的协议、域名和端口，而不是容器内部地址或错误的本机地址；修改配置并重启后再核对发布查询结果。

### 为什么未登录也能调用 GIS 管理接口

这是 v0.0.1 拦截器对 `/api/gis` 前缀整体放行造成的现状，不是推荐使用方式。生产环境必须在外层限制访问，并安排后续版本修复服务端授权。
